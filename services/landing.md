# landing-web — reference

> Собрано из `outegro/final-docs-outegro/09-landing.md` и `outegro/docs/OUTEGRO.md` §9.1.
> Это не код — это наработки для следующего обсуждения.

## Что это

- **Домен:** `outegro.com` (root).
- **Стек:** Next 16 standalone Node (`output: "standalone"`), за Traefik'ом.
- **Назначение:** публичная витрина — список всех продуктов, CTA «войти/регистрация» → `auth.outegro.com`.

## Особенности (отличается от других фронтов)

- **Liquid-glass дизайн, анимации, "невероятный адаптив".** Это требование к дизайн-системе, а не к инфре. В шаблоне `apps/example-frontend` есть базовые Tailwind 4 токены; для landing нужно расширить (палитра, motion, glassmorphism).
- **Данных почти нет.** Список сервисов — статический конфиг в репо на старте. Потом (если понадобится) — ConfigMap или API в meta-сервисе (AUDIT #47).
- **Секретов нет.**
- **Публичный статический кеш** — Cloudflare edge кеширует ассеты.

## Wiring

- 2 реплики + RollingUpdate (стандарт).
- Опционально `@outegro/contracts` (если рендерит общие данные), иначе самодостаточен.
- BFF route handlers для любых server-only фич (аналитика, ...).
- i18n через `next-intl` (en + ru в шаблоне есть).

## Что вынести в следующий проход

- **Продуктовый реестр** — где лежит список сервисов (статика → ConfigMap → meta-сервис).
- **Дизайн-система** — палитра/токены/типографика. Зафиксировать в `STACK.md` или отдельном `design-tokens.md`, чтобы не разъехалось по продуктам (AUDIT #69).
- **Motion** — какие анимации должны быть, какие библиотеки (`motion` уже в шаблоне).
- **i18n routing** — нужен ли URL-based (`/en`, `/ru`) или cookie-only (AUDIT #68).
